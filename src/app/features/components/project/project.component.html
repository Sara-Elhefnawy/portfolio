Backend .NET | Clean Architecture
ECommerce API - Minimal APIs, CQRS & Stripe

A production-style e-commerce backend built with ASP.NET Core Minimal APIs and a vertical-slice, CQRS architecture. Covers the full flow: catalog, cart, orders, email verification, password reset and card payments with Stripe webhooks.

What I built:
  • Endpoints auto-registered through a reflection-based IEndpoint pattern, versioned with ApiVersionSet
  • Pipeline behaviors for logging and FluentValidation, plus a unified ApiResponse<T> envelope
  • Stripe payments: order moves Pending → Processing / PaymentFailed via webhook events
  • HybridCache (in-memory + Redis) for cart data, with expiry policies set in appsettings
  • Audit logging with an IEndpointFilter and Serilog writing to PostgreSQL
  • Paginated product queries using the Specification pattern
Quality & testing:

Architecture tests (NetArchTest) enforce layer boundaries; integration tests use WebApplicationFactory + Testcontainers; NBomber load tests.

Concepts I used:
CQRS Vertical Slice Repository pattern Webhooks Distributed caching

Backend .NET | Modular Monolith
School Portal - Modular Monolith

A rebuild of my two-app School Portal. The original was two separate apps talking over HTTP ("accidental microservices"); this version merges them into one deployable with strict module boundaries, so modules communicate through events instead of network calls.

What I built:
  • Students, Grades, Attendance, Notifications and Identity modules, each with its own Domain / Application / Infrastructure projects
  • One PostgreSQL schema per module; EF Core for writes, Dapper only for GPA and ranking reports
  • Hand-built mediator in a SharedKernel, with cross-module domain events
  • Cookie auth with ASP.NET Core Identity, Admin / Teacher / Student roles, CSRF protection, email confirmation and password reset
  • Per-module health checks (/health/live, /health/ready)
  • Architecture tests that fail the build if a module reaches into another module's layers
Design decisions:

Private constructors + Result-returning factory methods in the domain, soft deletes with matching restore methods, and admin overrides as explicit named methods instead of boolean bypass flags.

Concepts I used:
Modular Monolith CQRS Domain events Result pattern Role-based auth
ASP.NET Core Minimal APIs EF Core Dapper PostgreSQL Identity NetArchTest Brevo

Gym System - ASP.NET Core MVC

A gym management app for members, plans, trainers and session bookings, built as an N-Tier solution (Domain, Infrastructure, UI) with cross-cutting concerns like soft delete and auditing handled automatically at the database layer.

Backend .NET | Testing
Library System - Integration & Load Tests

A test suite for a Library Management API that runs against a real SQL Server in a container, not a mock, so the tests catch the problems that only show up with a real database: migrations, serialization and query translation.

What I built:
  • Integration tests with xUnit + WebApplicationFactory hitting the real HTTP pipeline
  • Testcontainers spins up a disposable SQL Server per test run, so no manual DB setup
  • NBomber load scenarios measuring throughput and latency under concurrent users
  • One shared LibraryDataSeeder feeding both integration and load tests, so they use identical data
  • Readable assertions with Shouldly
Problems I solved:

Container startup and Docker issues, EF Core migrations running inside the test host, and circular JSON serialization in API responses.
